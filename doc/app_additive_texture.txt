:line

app_style additive/texture command :h3
app_style additive/texture/kk command :h3

[Syntax:]

app_style style nspins dx dt nrefine :pre

style = {additive/texture} or {additive/texture/kk} :ulb,l
nspins = number of possible Potts model spins :l
dx = lattice spacing in meters (SI) :l
dt = simulation timestep in seconds (SI) :l
nrefine = number of boundary-smoothing passes a site receives after it
solidifies (one pass per timestep) :l,ule

The legacy style name {additive_temperature_texture} is accepted as a
deprecated alias of {additive/texture}; using it prints a warning at
parse time.  The older form that passed a temperature file on the
app_style line is rejected; use
"setup_temperature_source"_setup_temperature_source.html instead.

[Examples:]

app_style additive/texture 1000000 5e-6 5e-6 2
app_style additive/texture/kk 1000000 3e-6 2e-6 1 :pre

[Description:]

These are on-lattice additive manufacturing (AM) applications derived
from "app_style potts/quaternion"_app_potts_quaternion.html.  They
simulate melting, solidification, and texture evolution driven by an
externally-supplied temperature field.  Crystallographic orientations
are tracked on each site as unit quaternions, and grain mobility is
biased by the local thermal gradient direction so that columnar /
textured solidification and competitive grain growth emerge naturally.

Style {additive/texture} is the CPU application.  Style
{additive/texture/kk} is the Kokkos (GPU) port, part of the KOKKOS
package: it implements the same model with every per-step operation
(temperature evaluation, melting, nucleation, solidification,
smoothing, powder activation) in device kernels, and is the
application used for production builds.  The two styles share one
temperature-source and command layer, so an input deck runs on either
after changing the style name and the "sweep"_sweep.html command (see
the restrictions below), unless it uses a command only one style
accepts.

The temperature field is provided by a modular {temperature source}
selected with the
"setup_temperature_source"_setup_temperature_source.html command.
The following sources are available:

"rosenthal"_temperature_source_rosenthal.html : steady-state
moving-frame analytical solution (point source, anisotropic point
source, or surface point + line-source keyhole). :ulb,l
"moser"_temperature_source_moser.html : unsteady time-domain Green's
function convolution of an ellipsoidal Gaussian source moving along a
path; supports a Goldak-style overlapping double-ellipsoid keyhole
mode and stochastic source-width and power fluctuations. :l
"conduction"_temperature_source_conduction.html : nonlinear
finite-volume heat conduction with temperature-dependent properties
and latent heat, on a stretched thermal grid that can extend past the
lattice box.  {additive/texture/kk} only. :l
"hdf5_unstructured / hdf5_csr"_temperature_source_hdf5.html : reads
time-resolved unstructured FE thermal data from HDF5 files and
interpolates it to lattice sites.  Requires a build with HighFive. :l,ule

The {rosenthal}, {moser}, and {conduction} sources consume a
"laser_path"_laser_path.html command that defines the laser
trajectory in world coordinates, and the {moser} source optionally
consumes "laser_fluctuations"_laser_fluctuations.html commands that
attach Power Spectral Density (PSD) noise streams to the source widths
and power.

Material values (liquidus, solidus, solidification-front velocity,
nucleation parameters, and the source's thermal properties) can be
taken from a TOML material card with the "material"_material.html
command.  Once a card is loaded there are no built-in defaults: each
of {liquidus}, {solidus}, {solid_front_vel}, {nucleation_density},
{critical_undercooling}, {undercooling_deviation},
{mean_nuclei_volume}, and {nuclei_volume_deviation} must come from the
card or from the deck, or the run stops with an error listing the
missing ones.  Deck commands issued after {material} override the
card.  See docs/MATERIAL_CARDS.md in the source tree for the card
format.

Each timestep the application: (1) evaluates T(x,y,z,t) at every
site from the temperature source; (2) melts every site with T >=
liquidus, giving it a random spin and orientation; (3) for liquid
sites below the liquidus, either nucleates a new grain (when the
site's spin is a nucleation spin and the undercooling exceeds that
spin's critical undercooling) or advances a solidification front by
v(dT)*dt, where v is the {solid_front_vel} velocity; once the front
has crossed the voxel, the site copies the orientation of a solid
parent grain chosen with probability weighted by the gradient-aligned
mobility (see {texture_parameters}); (4) applies one boundary-smoothing
pass to each site still inside its {nrefine}-pass window; (5) on the
first melt, and after a fast-forward skip, activates inactive sites at
or below the top of the melt pool (active_flag 0 -> 1).  Idle periods
with no liquid and the laser away from the domain are skipped by a
fast-forward predictor.

All physics runs inside the application's per-step update.  Both
styles run in app_update_only mode, so the rKMC site sweeps
requested by the "sweep"_sweep.html command are never performed; a
sweep command is still required to select the update loop, and the
timestep is {dt} from the app_style command.

Differences in the {additive/texture/kk} style:

Temperatures are evaluated on the device for all sources, and are
copied back to the host only when a host consumer needs them (output
steps, "stats"_stats.html, diagnostics); dumps and diagnostics at
output steps see current values. :ulb,l
{temperature_smooth} forces the host temperature path (slower), and
is not supported with the conduction source. :l
Solidification and smoothing kernels run in parallel over
an 8-colour parity ordering of the lattice, so the lattice spacing in
lattice units must be 1 (see Restrictions). :l
Nucleation always uses the threshold model ({nucleation_mode} is not
available). :l
The timestep check dt <= dx / v(Tl - Ts) is a warning instead of an
error. :l
The {floor_check} command is available. :l,ule

The temperature field (d6) is deterministic and matches bit for bit
between the two styles.  {additive/texture} microstructure output is
also repeatable for a given seed and processor count: every random draw
of a site's events in a step comes from a stream keyed by the seed, the
step and the site's global ID, and the per-spin nucleation properties
from one keyed by the seed and the spin ({misorientation_grain_walk}
is a fixed function of the grain and level, independent of the seed).
Rerunning a deck therefore reproduces it: replicate runs must use
different seeds.  Microstructures from versions before 2026-10-22, which
were not repeatable, cannot be reproduced.  A change at one site (a void
added with "set i2 hdf5 ... skip_novalue", say) therefore alters the
microstructure only through the physics around it, so runs with and
without voids can be compared site for site.  A different processor
count changes the update order at subdomain boundaries and gives a
different microstructure.  {additive/texture/kk} is repeatable in the
same way on each Kokkos backend, at any number of OpenMP threads
(different backends, e.g. HIP and OpenMP, give different
microstructures from the same seed): its kernels
draw from streams keyed by the seed, step, rank, site and kernel, the
solidification and smoothing kernels sweep the 8 parity colours in a
per-step order keyed by the seed, and the nuclei of a step grow one
after another in site order, so a contested liquid site always goes to
the same nucleus.  Its per-spin nucleation tables are the CPU app's.
The two styles still differ from each other (sequential vs coloured
update order), and kk microstructures from versions before 2026-10-22
cannot be reproduced.

[Application-specific commands:]

These commands are accepted by both styles unless noted.

Thermal and material properties:

{liquidus} {Tl} : liquidus temperature in K (> 0). :ulb,l
{solidus} {Ts} : solidus temperature in K (> 0). :l
{solid_front_vel} {N c0 c1 ... cN-1} or {power a n} : solidification-front
velocity in m/s, with dT the undercooling below the liquidus in K: the
polynomial v(dT) = c0*dT^(N-1) + c1*dT^(N-2) + ... + cN-1, or the power
law v(dT) = a*dT^n (a > 0, n > 0). :l
"material"_material.html {file} \[process {name}\] : load a material
card; sets the values above and the nucleation values below from the
card, and supplies {card} values to
"setup_temperature_source"_setup_temperature_source.html and
"laser_path"_laser_path.html. :l,ule

Nucleation:

{nucleation_density} {n0} : volumetric nucleation density in sites
per m^3 (>= 0).  Each spin is a nucleation spin with probability
n0*dx^3. :ulb,l
{critical_undercooling} {dTc} : mean critical undercooling for
heterogeneous nucleation in K (>= 0). :l
{undercooling_deviation} {sigma_T} : standard deviation of the
critical undercooling distribution in K (>= 0). :l
{mean_nuclei_volume} {Vn} : mean volume of a newly nucleated grain in
m^3 (>= 0). :l
{nuclei_volume_deviation} {sigma_V} : standard deviation of the
nucleated grain volume in m^3 (>= 0). :l
{nucleation_mode} {threshold|continuous} : threshold nucleates when
the undercooling first exceeds the spin's critical value; continuous
nucleates with a probability per timestep given by the Gaussian
undercooling distribution times the undercooling increment
(requires {undercooling_deviation} > 0).  {additive/texture}
only. :l,ule

Texture and misorientation:

{crystal} {name} \[{gx gy gz}\] : crystal symmetry and preferred
growth direction.  {name} = {cubic} (default), {hcp}, {trigonal},
{tetragonal} or {orthorhombic}, with the same symmetry sets and crystal
frames as "potts/quaternion"_app_potts_quaternion.html.  The growth
directions are {gx gy gz} (crystal-frame Cartesian components, default
0 0 1) and every direction equivalent to it under the symmetry: cubic
\[001\] gives the <100> family of the default model, hcp, tetragonal
and orthorhombic \[001\] the c axis alone, cubic 1 1 1 the four <111>
directions.  The growth directions are what the mobility angle theta
and {misorientation_target random} use.  The symmetry also sets the
disorientation for the new-grain test of {additive/texture}
({additive/texture/kk} uses the direct quaternion angle there). :ulb,l
{texture_parameters} {c2 c3} : mobility model
mob(theta) = 1 + c2 * cos(c3 * theta), where theta is the angle
between the local thermal gradient and the nearest growth direction
(see {crystal}).  {c2 >= 0} and {c3 >= 0} are enforced, and at the
start of each run {c3 * theta_max <= pi} (monotonicity), where
theta_max is the largest angle a gradient can make with its nearest
growth direction: acos(1/sqrt(3)) = 54.7 deg for cubic <100>, 90 deg
for a single axis such as hcp \[001\] (so c3 <= 2 there; the default
c3 = 2.5 needs a texture_parameters command).  A negative mobility is
allowed and gives the candidate zero weight.  The old three-argument form (c1 c2 c3) is
rejected with a message explaining the conversion. :l
{misorientation_diffusion} {D} \[{thresh}\] \[{alpha}\] : per-hop
random-walk rotation of each solidifying site relative to its parent,
by an angle sqrt(D_eff * hop) for a hop of length hop (m), so the
accumulated mean-square misorientation is D times the distance
grown.  {D} is in deg^2/m (0 = off).  {thresh} (deg, default 2): a
single step at or above it starts a new grain.  {alpha} (default 0 =
constant D): D_eff = D * g(dT/(Tl-Ts))^2 with
g(x) = (exp(alpha x)-1)/(exp(alpha)-1).  A warning is printed if
sqrt(D*dx) reaches {thresh}. :l
{misorientation_grain_walk} {D} \[{rho}\] \[{path|height}\] : coherent
per-grain rotation walk in deg^2/m (0 = off).  {rho} in \[0,1)
(default 0) correlates the rotation axis between levels (persistent
bending); the level is the inheritance path length in lattice units
({path}, default) or the lattice z level ({height}). :l
{misorientation_target} {random_rotation|random} : rotation axis of
the misorientation step; {random_rotation} (default) rotates about a
uniformly random axis, {random} rotates the nearest growth direction
(<100> for the default {crystal}) toward a random direction. :l
{nucleation_misorientation_target} {on|off|none} : when on (default)
and {misorientation_diffusion} is active, the sites a nucleus claims
take one walk step of sqrt(D_eff * distance from the seed) relative
to the seed. :l,ule

The former commands {misorientation_function} and
{misorientation_cap}, and the {gradient} option of
{misorientation_target}, were replaced by {misorientation_diffusion}
and {random_rotation}; they now stop with an error.

Boundary smoothing (applied during the {nrefine} window):

{smooth_greedy_multiproposal} {on|off} : evaluate every distinct
neighbor spin and adopt the energy-minimizing one (steepest descent)
instead of testing one random proposal per pass.  Default off. :ulb,l
{smooth_orientation} {average|copy} : a site that changes grain takes
the sign-aligned average orientation of its neighbors in that grain
({average}, default) or the orientation of one of them ({copy}). :l
{nuclei_smooth} {on|off} : when on, nucleated sites enter the
smoothing window like epitaxially solidified sites; when off
(default) they are not smoothed. :l
{single_voxel_cleanup} {on|off} : after a voxel exits the {nrefine}
window, if its full 26-neighbor shell is solidified (voids aside) and
contains no same-spin neighbor, flip it to the energy-minimizing
neighbor grain.
Default off.  {additive/texture} only. :l,ule

Temperature source plumbing:

"setup_temperature_source"_setup_temperature_source.html
{type} followed by source-specific args : choose and configure the
temperature source.  Required. :ulb,l
"laser_path"_laser_path.html
{start X0 Y0 Z0 end X1 Y1 speed V} with optional {repeats}, {hatch},
{serpentine}, {pause}, {pause_below}, {reset_temperature} keywords,
or {file F speed V ...} for a waypoint file (Moser and conduction
sources) : defines the laser trajectory. :l
"laser_fluctuations"_laser_fluctuations.html
{psd} \[{top|bot|both}\] {shape} {keyword value ...} : attach PSD
noise streams to the Moser source widths and power; must precede
{laser_path}. :l
{fast_forward_search_window} {seconds} : time step (> 0) of the
look-ahead walk the Rosenthal and Moser fast-forward predictors use to
find the next time the laser heats the domain.  Default 0.1 s; short
runs need a value well below the run length. :l,ule

Temperature post-processing:

{temperature_smooth} {tmin tmax sigma_xy sigma_z} \[{alpha}\]
\[{guard}\] \[{passes}\] \[{diag_interval}\] : opt-in Gaussian smoothing
of the temperature field inside the window tmin..tmax (K), intended
for the solidification band.  {sigma_xy}, {sigma_z} are in sites;
{alpha} (default 0.4, in \[0,1\]) is the blend factor; {guard}
(default 20 K) is a soft taper outside the window; {passes} (default
1); {diag_interval} (default 0 = off) prints an isotherm diagnostic
every that many steps. :ulb,l
{nodal_smooth} {sigma_xy sigma_z passes alpha} : nodal mesh-Laplacian
smoothing of the temperature data at the source level; applies to
the HDF5 sources (no-op for the others).  Must follow
{setup_temperature_source}. :l,ule

Voids (porosity), {additive/texture} only:

{void_density} {n} : volumetric pore density in voids per m^3.
Mutually exclusive with {void_pore_fraction}. :ulb,l
{void_pore_fraction} {f} : target volumetric pore fraction in
\[0, 1).  Mutually exclusive with {void_density}. :l
{void_size_distribution} {mean std min max} : truncated normal
distribution of pore radii in micrometers.  Default 75 25 0 150.
The voids fill the run's box; in a box-per-layer chain every box
adds a set of its own, so use a void mask (below) there instead. :l,ule

Box-per-layer builds, {additive/texture/kk} only:

{floor_check} {d} : stop the run with an error if liquid comes within
{d} meters of the bottom of the box (0 = off, the default).  The
error is raised before the run's stitch dump is written, so a box
whose melt pool reaches the floor can be rerun deeper.  The app also
prints "floor_check: deepest liquid z = ..." each time the deepest
liquid site moves down, which a driver script can use to size the
next box.

[Site state:]

Both styles have 2 integer and 10 double per-site values, addressed as
i1, i2 and d1 ... d10 by the "set"_set.html, "dump"_dump.html, and
"diag_style"_diag_style.html commands:

i1      = spin (grain ID)
i2      = active_flag (0 = inactive, 1 = active solid/powder,
                       2 = liquid, 3 = solidified, 5 = void)
d1..d4  = (q0, qx, qy, qz) unit quaternion
d5      = mobility_out
d6      = T (temperature, K)
d7      = solid_d (front distance while liquid; smoothing-pass countdown after)
d8      = G (thermal gradient magnitude at solidification)
d9      = V (solidification rate at solidification)
d10     = path length from the grain origin, lattice units ({misorientation_grain_walk path}) :pre

Substrate vs. powder layers and the per-site initial state are set
with the "set"_set.html command before the run.  Sites with i2 = 1 or
3 act as solid parents; sites left at i2 = 0 are activated (set to 1)
once the melt pool reaches their height.  At the start of the run,
{additive/texture} gives a random orientation to every site with
i2 != 3; {additive/texture/kk} gives one to every site whose
quaternion is zero (and normalizes the others).

Baseplate sites (i2 = 6, {additive/texture/kk} with the
"conduction"_temperature_source_conduction.html source and its
{plate_material} keyword) take the plate's thermal properties and
liquidus.  They are solid parents like i2 = 3, and sites that solidify
below the plate surface return to 6.

Void sites (i2 = 5) are permanent in both styles.  They are thermally
air (the conduction source treats them as gas), never melt, solidify,
or become powder, and never lend their spin or orientation to a
neighbour.  {additive/texture} can generate spherical voids with the
void commands above.  Measured (CT) defects are applied as a mask
written by tools/ct_defects.py from a .glb mesh export: at their
measured positions (crop), sampled uniformly from the population
(sample), or as a tile bootstrap that keeps the measured clumping and
depth below the part surface (cluster; the surface is the edge of the
scanned footprint from a laser_path line, a waypoint file, G-code, or
an HDF5 thermal file):

set i2 hdf5 mask.h5 skip_novalue :pre

The mask is keyed by absolute lattice index, so one file that covers
the whole build can be applied in every box of a box-per-layer run
(examples/am/surge/gp700_moser/run_layers.sh: DEFECTS=mask.h5).

A box-per-layer build continues the microstructure from a stitch file
(STITCH package) by dumping and reloading i1 i2 d1 d2 d3 d4 d8 d9 d10,
e.g. "set i2 stitch file last".

[Restrictions:]

These styles are part of the core build but are compiled only when
SPPARKS is built with MPI.  Style {additive/texture/kk} also requires
the KOKKOS package.  The hdf5_unstructured and hdf5_csr temperature
sources require a build with HighFive (and parallel HDF5); without it
they stop with an error at input time.

The lattice must be simple cubic with 26 neighbors (lattice sc/26n
1.0); site coordinates are converted to meters by multiplying by
{dx}.  Style {additive/texture/kk} checks this and stops with an error
on any other lattice spacing.

A "sweep"_sweep.html command is required.  For
{additive/texture}, any rKMC sweep style works (e.g. "sweep random
mask no"); in parallel, random and raster sweeps need "sector
yes"_sector.html.  Style {additive/texture/kk} requires "sweep color"
(or {color/strict}, which is accepted but does not make this
application repeatable).  A KMC solver cannot be used.  No sweep is
ever performed: each step advances time by the thermal timestep {dt},
so the sweep style does not change results.  The "sector"_sector.html
{nstop} option must be left at 1 and {tstop} unset, since the step is
{nstop} times {dt}; both styles stop with an error otherwise.

Style {additive/texture/kk} runs on multiple MPI ranks, one GPU per
rank (ranks are bound to GPUs by node-local rank).  The conduction
source requires a "processors"_processors.html grid that does not
split z.  Style {additive/texture/kk} rejects the {additive/texture}-only commands above
({nucleation_mode}, {single_voxel_cleanup}, {void_density},
{void_pore_fraction}, {void_size_distribution}) as unrecognized, and
{additive/texture} rejects {floor_check} and stops at the first
temperature query when the conduction source is selected.

The "create_sites"_create_sites.html command must be called before
the first temperature query.

See docs/AM_KOKKOS_PLAN.md and docs/CONDUCTION_SOURCE.md in the source
tree for implementation details of the Kokkos port and the
conduction source.

[Default:]

The defaults are the same for both styles except where two values are
given.

liquidus = 1723 K, solidus = 1673 K
solid_front_vel = 4 1.091e-5 -2.034e-4 2.74e-3 1.151e-4
nucleation_density = 1e15
critical_undercooling = 5 K, undercooling_deviation = 3 K
mean_nuclei_volume = 2*dx^3, nuclei_volume_deviation = dx^3
mobility = 0.5 + 0.5*cos(2.5 theta) until texture_parameters is given
  (the same ratios as texture_parameters 1 2.5)
misorientation_diffusion off (thresh 2 deg, alpha 0)
misorientation_grain_walk off
crystal = cubic 0 0 1 (the <100> growth family)
misorientation_target = random_rotation
nucleation_misorientation_target = on
smooth_greedy_multiproposal = off, smooth_orientation = average, nuclei_smooth = off
nucleation_mode = threshold, single_voxel_cleanup = off (additive/texture)
floor_check = 0 (off) (additive/texture/kk)
fast_forward_search_window = 0.1 s
temperature_smooth off, nodal_smooth off
voids off (additive/texture) :pre

With a "material"_material.html card loaded, the material defaults
above do not apply.
