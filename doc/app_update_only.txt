app_update_only command :h3

[Syntax:]

app_update_only flag :pre

flag = {yes} or {no} :ul

[Examples:]

app_update_only yes :pre

[Description:]

Choose whether a run performs only the application's own update
routine instead of Monte Carlo events.  Some on-lattice applications
define an update routine (app_update) that advances their state
directly, e.g. a finite-difference field step or a moving heat source.
By default (no) it is called after each KMC event or rKMC sweep.  With
{yes} the KMC events and rKMC site sweeps are skipped: each timestep
is one call of the update routine, followed by output.

The timestep is the application's sweep time (one sweep's worth of
time, set by the application).  When no KMC solver is defined, an
update-only run needs no "sweep"_sweep.html command; if one is given,
any sweep style is accepted, and random or raster sweeps need no
sectors in parallel, since the sweep is never performed.

These applications permit {yes}: potts/anneal, potts/rx, sinter,
phasefield, phasefield/potts, phasefield/potts/table, am/ellipsoid,
potts/am/bezier, additive/texture (and the /kk variants of these), and
diffusion with batch "deposition"_deposition.html.  The additive/texture and phasefield styles (and their /kk
variants) always run update-only and set {yes} themselves.

[Restrictions:]

This command can only be used with on-lattice applications that define
an update routine; with any other application, {yes} is an error.

[Related commands:]

"sweep"_sweep.html, "solve_style"_solve_style.html

[Default:]

The default is no, except for the applications listed above that set
{yes} themselves.
