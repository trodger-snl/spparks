:line

laser_fluctuations command :h3

[Syntax:]

laser_fluctuations psd \[top|bot|both\] shape keyword value ... :pre

selector = optional {top}, {bot}, or {both} for the
"moser keyhole"_temperature_source_moser.html mode (required in
keyhole mode, rejected in standard mode) :ulb,l
shape = one of {white}, {lorentzian}, {pink}, {narrow_band} :l
keyword/value pairs in any order : :l
sigma_W : RMS fractional fluctuation of the lateral widths (sx, sy),
          >= 0; default 0.0 :l
sigma_D : RMS fractional fluctuation of the depth width (sz), >= 0;
          default 0.0 :l
sigma_P : RMS fractional fluctuation of this lobe's absorbed power,
          >= 0; default 0.0 :l
rho : Pearson correlation between the W and D draws, in \[-1, 1\];
      default 0.0 :l
seed : RNG seed (integer); default 12345.  Every MPI rank generates the
       same stream from it, so no broadcast is needed. :l
dt : sample spacing of the fluctuation table in seconds, > 0; default
     5e-6.  The table is linearly interpolated at each emission time,
     so dt need not match the timestep. :l
tau : correlation time in seconds, > 0 (lorentzian; required) :l
f0 : center frequency in Hz, > 0 (narrow_band; required) :l
df : bandwidth in Hz, > 0 (narrow_band; required) :l,ule

[Examples:]

# Standard (single ellipsoid) Moser source:
laser_fluctuations psd lorentzian sigma_W 0.05 sigma_D 0.06 tau 200e-6 &
                  rho 0.5 seed 12345 dt 5e-6 :pre

# Moser keyhole, independent streams on cap and depth:
laser_fluctuations psd top lorentzian sigma_W 0.05 sigma_D 0.06 &
                  tau 200e-6 rho 0.5 seed 12345 dt 5e-6
laser_fluctuations psd bot lorentzian sigma_W 0.08 sigma_D 0.10 &
                  sigma_P 0.20 tau 500e-6 rho 0.3 seed 67890 dt 5e-6 :pre

# Moser keyhole, "both" sugar (same shape and sigmas; bot's seed is
# derived from top's via SplitMix64 XOR for independent streams):
laser_fluctuations psd both lorentzian sigma_W 0.05 sigma_D 0.06 &
                  tau 200e-6 rho 0.5 seed 12345 dt 5e-6 :pre

See examples/am/surge/validation/in.moser_pause_below.cpu (and .kk) for a
standard-mode deck.

[Description:]

Attaches a Power Spectral Density (PSD) noise stream to one or both
lobes of the "moser"_temperature_source_moser.html source so that the
ellipsoid widths and absorbed power fluctuate around their nominal
values.  When the scan is built, the stream is sampled every {dt}
seconds over the scan's emitting window into a table of
multiplicative factors.  Because the Moser integral evaluates the
source at each emission time with that emission's factors,
cooling-tail sites keep the fluctuations that heated them rather than
snapping to the latest values each step.

This is the Moser-source feature that distinguishes it from the
Rosenthal source for fluctuation studies; the Rosenthal kernel is
steady-state and cannot represent per-emission parameter histories.

The four available PSD shapes are:

{white} : uncorrelated Gaussian draws each {dt}.  Flat spectrum. :ulb,l
{lorentzian} : exponentially-correlated Gaussian process via a
discrete first-order AR(1) filter with correlation time {tau}.
Spectrum 1 / (1 + (omega tau)^2). :l
{pink} : approximately 1/f noise via the Voss-McCartney algorithm:
the sum of 6 independent levels, level k redrawn every 2^k samples. :l
{narrow_band} : damped harmonic oscillator driven by white noise,
with natural frequency {f0} and damping ratio {df} / (2 {f0})
(clamped below 1).  Spectrum peaks near {f0}. :l,ule

Each shape is scaled so its stationary RMS is the given sigma, and
the chain is warmed up for 1000 samples before the table starts.

With dW, dD, dP the sampled values, the source uses sx*(1+dW),
sy*(1+dW), sz*(1+dD) and power*(1+dP).  The width factors are clamped
to >= 1e-3 and the power factor to >= 0; a warning is printed if any
|d| exceeds 0.5, where this first-order model stops being accurate.
The W and D draws are correlated by {rho}; the P draw is independent.

The table is regenerated whenever the scan is rebuilt.  When a pass is
appended under {pause_below}, the table restarts from the scan's
first pass with the same seed, so earlier samples are unchanged.  When
the table starts later than t = 0 (e.g. a pass fired with
{reset_temperature}, or a {laser_path} issued in a later run), the seed
is mixed with that start time, so each such pass gets a different but
reproducible stream.

:line

[top|bot|both selector (Moser keyhole mode):]

In "moser keyhole"_temperature_source_moser.html mode the source has
two lobes (TOP cap and BOT depth) and the selector is required:

{top} : configure the top (cap) lobe only :ulb,l
{bot} : configure the bottom (depth) lobe only :l
{both} : sugar - apply the same shape and sigmas to both lobes.  The
bottom-lobe seed is derived as
{top_seed XOR 0x9E3779B97F4A7C15ULL} (the SplitMix64 golden constant)
so the streams are statistically independent yet
MPI-deterministic. :l,ule

To configure the two lobes with {different} shapes or sigmas (the
typical canonical case for vapor-driven keyhole instabilities), issue
two {laser_fluctuations} commands - one with {top}, one with {bot}.

In Moser standard mode the selector must be omitted; supplying it
raises an error.

:line

[Required ordering:]

setup_temperature_source moser ...
laser_fluctuations psd \[selector\] shape ...
laser_path start ... end ... speed ... :pre

The fluctuation table is built by "laser_path"_laser_path.html
(either form), once the scan duration is known, so
{laser_fluctuations} must be issued after {setup_temperature_source}
but before {laser_path}.  The reverse order is an error:

laser_fluctuations must be issued BEFORE laser_path ... :pre

rather than a silent no-op (the spec would otherwise be stored on the
source but never materialized into a fluctuation table).

:line

[Power conservation note:]

Total absorbed power is {not} conserved through fluctuations.  In
keyhole mode,

P_total(t) = lambda Q \[1 + f_top dP_top(t) + f_bot dP_bot(t)\] :pre

so {var(P_total) / (lambda Q)^2 = f_top^2 sigma_P_top^2 +
f_bot^2 sigma_P_bot^2} for uncorrelated streams.  This is by design:
the keyhole vapor cavity is a much stronger laser absorber than the
solid/liquid metal, and the resulting intermittent absorption is one
of the experimentally-observed drivers of unsteady keyhole behavior.
A typical canonical setup is {sigma_P_bot ~ 0.20} with
{sigma_P_top ~ 0.01}.

:line

[Restrictions:]

Only the "moser"_temperature_source_moser.html source supports
{laser_fluctuations}.  The command is an error with a Rosenthal or
HDF5 source; with the
"conduction"_temperature_source_conduction.html source it is accepted
but the run stops with an error.

[GPU support:]

Fluctuations work in {additive/texture} and {additive/texture/kk}.
In the Kokkos app the fluctuation tables are uploaded to the device
and the fluctuating Green's-function integral is evaluated there, for
both Moser modes and all pass schedules.
