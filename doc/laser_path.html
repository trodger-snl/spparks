laser_path command

Syntax: 

laser_path start X0 Y0 Z0 end X1 Y1 speed V     repeats N pause T | pause_below Tk
  • X0, Y0, Z0 = path start coordinates in meters (Z0 is the laser plane)
  • X1, Y1 = path end coordinates in meters (the path is at constant Z = Z0)
  • V = laser speed in meters per second (must be > 0)
  • N = number of times to replay the same linear segment back-to-back (default 1; must be >= 1)
  • T = constant inter-pass pause in seconds (default 0; must be > 0 if given); Moser source only
  • Tk = peak-temperature threshold in K that gates the inter-pass pause (default unset; must be > 0 if given); Moser source only

pause and pause_below are mutually exclusive.

Examples: 

laser_path start 0.25e-3 0.20e-3 0.30e-3 end 1.75e-3 0.20e-3 speed 1.2
laser_path start 0.25e-3 0.20e-3 0.30e-3 end 1.75e-3 0.20e-3 speed 1.2 repeats 5
laser_path start 0.25e-3 0.20e-3 0.30e-3 end 1.75e-3 0.20e-3 speed 1.2 repeats 5 pause 1.0e-3
laser_path start 0.25e-3 0.20e-3 0.30e-3 end 1.75e-3 0.20e-3 speed 1.2 repeats 5 pause_below 700.0

Description:

Defines the laser trajectory consumed by the path-aware temperature sources used with app_style additive/texture. Coordinates and velocity are SI (meters and m/s). The path is a single linear segment in the (X, Y) plane at constant Z = Z0 (the laser plane); setting repeats > 1 replays the same start->end segment N times back-to-back. Each pass duration is 

dt_pass = sqrt((X1 - X0)^2 + (Y1 - Y0)^2) / V

so the total scan time is N * dt_pass. Subsequent commands (typically the run command) advance simulation time across the full scan and any post-scan cooling.

The active temperature source is updated as follows:

  • For the rosenthal source, the path is stored in scan_layer for use by the per-step Rosenthal evaluation and the fast-forward predictor. The 1/R singularity guard r_min is sized to 0.5 * dx.
  • For the moser source, the path is handed over to the source's build_scan method, which constructs the GREENAM LaserScan / ScanIntegration state for the active lobe(s) and materializes any pending PSD fluctuation tables.
  • For the hdf5_unstructured / hdf5_csr sources, this command is accepted but has no effect (the laser trajectory is implicit in the FE temperature trace).

Inter-pass pause (Moser only):

When repeats > 1 the pause and pause_below keywords control how much simulation time elapses between consecutive passes. Both apply only to the time-resolved Moser source. The rosenthal source rejects either keyword at parse time because the steady-state moving-point solution already gives physically independent passes (no thermal history carries across a back-to-back repeat).

  • pause T inserts a fixed cooling interval of T seconds between each pair of consecutive passes. The interval is realized inside the Moser/GREENAM scan as a zero-power transit segment, so the integrand naturally captures the cooling tail of the previous pass while no new heat is being deposited. The legacy 1e-12 s numerical floor on the inter-repeat time step is preserved automatically when pause = 0.
  • pause_below Tk fires each subsequent pass dynamically. Only the first pass is scheduled when laser_path is parsed; the remaining repeats - 1 passes sit in a queue. After the current pass finishes emitting, the simulation continues advancing time normally and the Moser integrand naturally cools. As soon as the global peak temperature drops below Tk, the next queued pass is appended to the Moser scan starting at the current simulation time, and emission resumes. This means: if the box is already below Tk when pass r ends, pass r+1 fires on the very next step (back-to-back); if the box stays hot, pass r+1 is held off until natural cooling brings it below Tk. The inter-pass gap is therefore not user-specified — it falls out of the physics.

The pause_below flow gates dynamic-fire on "the current pass has finished emitting" so that the laser warm-up window (where peak temperature is below Tk simply because not enough emission has accumulated) does not drain the queue prematurely.

Fluctuations interoperate with both modes. Under pause_below, the PSD fluctuation table is regenerated after each append_pass so that samples at original timestamps remain identical (deterministic in seed and t_start) and new samples extend the table to cover the appended pass.

Required ordering:

For the Moser source with fluctuations, the correct command order is 

setup_temperature_source moser ...
laser_fluctuations psd ...
laser_path start ... end ... speed ...

so that the fluctuation specs are in place when build_scan populates each lobe's PSD table. See laser_fluctuations for details.

laser_path requires that setup_temperature_source has already been called; otherwise the command exits with an error of the form 

laser_path: setup_temperature_source must be called first ...

Restrictions:

Currently only a single linear scan segment is supported per laser_path command (with optional N-fold replay). Multi-segment arbitrary-shape paths are not yet supported by the path-aware temperature sources; for arbitrary scan strategies use the hdf5_unstructured / hdf5_csr sources with an externally-prepared FE thermal trace.

Related commands:

setup_temperature_source, laser_fluctuations, app_style additive/texture

Default:

repeats = 1, pause = 0 s, pause_below = (use liquidus tl)
