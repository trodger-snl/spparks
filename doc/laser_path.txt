:line

laser_path command :h3

[Syntax:]

laser_path start X0 Y0 Z0 end X1 Y1 speed V \
    [repeats N] [pause T | pause_below Tk] [reset_temperature Tr] :pre

X0, Y0, Z0 = path start coordinates in meters (Z0 is the laser plane) :ulb,l
X1, Y1 = path end coordinates in meters (the path is at constant Z = Z0) :l
V = laser speed in meters per second (must be > 0) :l
N = number of times to replay the same linear segment back-to-back
    (default 1; must be >= 1) :l
T = constant inter-pass pause in seconds (default 0; must be > 0 if given);
    Moser source only :l
Tk = peak-temperature threshold in K that gates the inter-pass pause
     (default unset; must be > 0 if given); Moser source only :l
Tr = uniform temperature in K to reset the simulation domain to at
     each inter-pass boundary; requires `pause` or `pause_below`
     (default unset; must be > 0 if given); Moser source only :l,ule

{pause} and {pause_below} are mutually exclusive.
{reset_temperature} combines with either one.

[Examples:]

laser_path start 0.25e-3 0.20e-3 0.30e-3 end 1.75e-3 0.20e-3 speed 1.2
laser_path start 0.25e-3 0.20e-3 0.30e-3 end 1.75e-3 0.20e-3 speed 1.2 repeats 5
laser_path start 0.25e-3 0.20e-3 0.30e-3 end 1.75e-3 0.20e-3 speed 1.2 repeats 5 pause 1.0e-3
laser_path start 0.25e-3 0.20e-3 0.30e-3 end 1.75e-3 0.20e-3 speed 1.2 repeats 5 pause_below 700.0
laser_path start 0.25e-3 0.20e-3 0.30e-3 end 1.75e-3 0.20e-3 speed 1.2 repeats 5 pause 1.0e-3 reset_temperature 573
laser_path start 0.25e-3 0.20e-3 0.30e-3 end 1.75e-3 0.20e-3 speed 1.2 repeats 5 pause_below 700.0 reset_temperature 573 :pre

[Description:]

Defines the laser trajectory consumed by the path-aware temperature
sources used with
"app_style additive/texture"_app_additive_texture.html.
Coordinates and velocity are SI (meters and m/s).  The path is a single
linear segment in the (X, Y) plane at constant {Z = Z0} (the laser
plane); setting {repeats > 1} replays the same start->end segment N
times back-to-back.  Each pass duration is

dt_pass = sqrt((X1 - X0)^2 + (Y1 - Y0)^2) / V :pre

so the total scan time is {N * dt_pass}.  Subsequent commands
(typically the "run"_run.html command) advance simulation time across
the full scan and any post-scan cooling.

The active temperature source is updated as follows:

For the "rosenthal"_temperature_source_rosenthal.html source, the path
is stored in {scan_layer} for use by the per-step Rosenthal evaluation
and the fast-forward predictor.  The 1/R singularity guard {r_min} is
sized to {0.5 * dx}. :ulb,l

For the "moser"_temperature_source_moser.html source, the path is
handed over to the source's {build_scan} method, which constructs the
GREENAM {LaserScan} / {ScanIntegration} state for the active lobe(s)
and materializes any pending PSD fluctuation tables. :l

For the "hdf5_unstructured / hdf5_csr"_temperature_source_hdf5.html
sources, this command is accepted but has no effect (the laser
trajectory is implicit in the FE temperature trace). :l,ule

:line

[Inter-pass pause (Moser only):]

When {repeats > 1} the {pause} and {pause_below} keywords control how
much simulation time elapses between consecutive passes. Both apply
only to the time-resolved Moser source. The
"rosenthal"_temperature_source_rosenthal.html source rejects either
keyword at parse time because the steady-state moving-point solution
already gives physically independent passes (no thermal history
carries across a back-to-back repeat).

{pause T} inserts a fixed cooling interval of {T} seconds between
each pair of consecutive passes. The interval is realized inside the
Moser/GREENAM scan as a zero-power transit segment, so the integrand
naturally captures the cooling tail of the previous pass while no new
heat is being deposited. The legacy {1e-12 s} numerical floor on the
inter-repeat time step is preserved automatically when {pause = 0}. :ulb,l

{pause_below Tk} fires each subsequent pass dynamically.  Only the
first pass is scheduled when {laser_path} is parsed; the remaining
{repeats - 1} passes sit in a queue.  After the current pass finishes
emitting, the simulation continues advancing time normally and the
Moser integrand naturally cools.  As soon as the global peak
temperature drops below {Tk}, the next queued pass is appended to the
Moser scan starting at the current simulation time, and emission
resumes.  This means: if the box is already below {Tk} when pass {r}
ends, pass {r+1} fires on the very next step (back-to-back); if the
box stays hot, pass {r+1} is held off until natural cooling brings it
below {Tk}.  The inter-pass gap is therefore not user-specified — it
falls out of the physics. :l,ule

The {pause_below} flow gates dynamic-fire on "the current pass has
finished emitting" so that the laser warm-up window (where peak
temperature is below {Tk} simply because not enough emission has
accumulated) does not drain the queue prematurely.

Fluctuations interoperate with both modes.  Under {pause_below}, the
PSD fluctuation table is regenerated after each {append_pass} so that
samples at original timestamps remain identical (deterministic in
seed and t_start) and new samples extend the table to cover the
appended pass.

{reset_temperature Tr} can be combined with either {pause T} or
{pause_below Tk}.  At each inter-pass boundary (when the next pass is
about to fire), the entire Moser scan history is cleared (only the
new pass remains scheduled) and the source's ambient T0 is shifted to
{Tr}.  This simulates the simulation domain having completely cooled
to a uniform value before the new pass begins: subsequent temperature
queries return {Tr + integral_over_new_pass_only} with no Green's-
function tail from earlier passes.  Adding {reset_temperature} also
switches {pause T} from static N-pass pre-scheduling to per-pass
dynamic scheduling so the reset can be applied at each gap boundary;
this is transparent to the user but increases the per-pass rebuild
work proportionally to {repeats}.

:line

[Required ordering:]

For the Moser source with fluctuations, the correct command order is

setup_temperature_source moser ...
laser_fluctuations psd ...
laser_path start ... end ... speed ... :pre

so that the fluctuation specs are in place when {build_scan} populates
each lobe's PSD table.  See
"laser_fluctuations"_laser_fluctuations.html for details.

{laser_path} requires that "setup_temperature_source"_setup_temperature_source.html
has already been called; otherwise the command exits with an error of
the form

laser_path: setup_temperature_source must be called first ... :pre

:line

[Restrictions:]

Currently only a single linear scan segment is supported per
{laser_path} command (with optional N-fold replay).  Multi-segment
arbitrary-shape paths are not yet supported by the path-aware
temperature sources; for arbitrary scan strategies use the
"hdf5_unstructured / hdf5_csr"_temperature_source_hdf5.html sources
with an externally-prepared FE thermal trace.

[Related commands:]

"setup_temperature_source"_setup_temperature_source.html,
"laser_fluctuations"_laser_fluctuations.html,
"app_style additive/texture"_app_additive_texture.html

[Default:]

repeats = 1, pause = 0 s, pause_below = (use liquidus tl)
