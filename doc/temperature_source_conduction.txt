:line

setup_temperature_source conduction command :h3

[Syntax:]

setup_temperature_source conduction Q lambda k alpha T0 cp sx sy sz keyword values ...
setup_temperature_source conduction card overrides keyword values ... :pre

Q = laser power (W) :ulb,l
lambda = absorptivity; the absorbed power is lambda*Q :l
k = thermal conductivity (W/(m K)); with {k_table} it only sets the density :l
alpha = thermal diffusivity (m^2/s); the density is rho = k/(alpha*cp) :l
T0 = ambient and initial temperature (K) :l
cp = specific heat (J/(kg K)); with {cp_table} it only sets the density :l
sx, sy, sz = Gaussian source widths (m), as in "moser"_temperature_source_moser.html :l
{card} = take the positional values and material keywords from the loaded
"material card"_material.html; see "setup_temperature_source"_setup_temperature_source.html :l
zero or more keyword/value pairs may be appended :l
keyword = {k_table} or {cp_table} or {latent} or {k_powder} or {convection} or {emissivity} or {evaporation} or {evaporation_coef} or {evaporation_ambient} or {margin} or {plate} or {stretch} or {max_cell} or {part} or {layer_thickness} or {packing} or {plate_top} or {plate_material} or {plate_growth} or {composition} or {beam} or {far_bc} or {sts} or {carry} or {flow} or {init} or {far} or {ded} :l
  {k_table} values = n T1 k1 ... Tn kn
    dense conductivity k(T), piecewise linear, held at the end values (K, W/(m K))
  {cp_table} values = n T1 c1 ... Tn cn
    specific heat cp(T), piecewise linear, held at the end values (K, J/(kg K))
  {latent} value = L
    latent heat of fusion (J/kg), released linearly between solidus and liquidus
  {k_powder} value = k
    powder conductivity (W/(m K))
  {convection} values = h T_inf
    convective loss coefficient (W/(m^2 K)) and gas temperature (K)
  {emissivity} value = e
    radiative loss to T_inf
  {evaporation} values = n Tb Lv M ...
    evaporative loss from metal surfaces: n = 1 or 2 species, each with its
    boiling point at 1 atm (K), latent heat of vaporisation (J/kg) and molar mass (kg/mol)
  {evaporation_coef} value = c
    net fraction of the Hertz-Knudsen flux that leaves into vacuum (default 0.82)
  {evaporation_ambient} value = p
    ambient pressure (Pa, default 101325); 0 = vacuum
  {margin} values = xlo xhi ylo yhi
    thermal domain beyond the lattice box on each side (m)
  {plate} value = d
    thermal domain below the lattice box (m)
  {stretch} value = r
    width ratio of successive cells outside the box (>= 1)
  {max_cell} value = w
    cap on the width of cells outside the box (m)
  {part} value = region-ID
    outside the box, cells inside this region are dense, the rest powder
  {layer_thickness} value = t
    outside the box, cells within t of the laser plane are powder (m)
  {packing} value = f
    powder cells hold f times the dense mass, 0 < f <= 1
  {plate_top} value = z
    every cell below z is dense (m)
  {plate_material} value = file
    material card of the baseplate: the dense material of {i2} = 6 sites and of the cells below {plate_top}
  {plate_growth} value = d
    {i2} = 6 may reach d above {plate_top} (m)
  {composition} values = n x1 file1 ... xn filen [bins b] [mix m] [feed f]
    n >= 2 material cards at increasing compositions x1 < ... < xn;
    each site's composition is d11; b bins over x1..xn (default 21, 2..254);
    m = {pool} (default), {flow} or {none}: the melt pool is well mixed,
    the melt-pool flow carries the composition ({flow} keyword), or it does not change
    f = {slab} (default) or {surface}: how new material enters under {mix flow} with {ded}
  {flow} values = {lbm} [dsigma_dT s] [beta b] [viscosity nu] [mushy C] [u_ref u] [smagorinsky cs] [properties cards|constant] [sigma_table file]
    melt-pool flow (lattice Boltzmann) on the liquid cells of the lattice box
    s = surface tension's temperature coefficient (N/m/K, default -2.6e-4)
    b = volumetric thermal expansion of the liquid (1/K, default 1.7e-4)
    nu = kinematic viscosity (m^2/s, default 8.5e-7)
    C = mushy-zone drag constant (1/s, default 1e4)
    u = expected flow speed (m/s, default 1), sets the first flow step
    cs = Smagorinsky constant (default 0.17, 0 = off)
    properties cards = surface tension, density and viscosity of the liquid by composition, from the composition's cards (default constant: s, b, nu)
    file = table of surface tension over T and composition, with properties cards (default: from the cards)
  {beam} value = {gaussian} or {square}
    gaussian = exp(-x^2/sx^2) per axis; square = uniform over |x| <= sx, |y| <= sy (a top-hat of side 2 sx by 2 sy; the depth profile is unchanged)
  {far_bc} value = {fixed} or {adiabatic}
    outer faces of the thermal domain held at T0, or insulated
  {sts} value = s
    RKL2 stages per laser-off super-step, 0 = explicit steps only, or >= 2
  {carry} value = {yes} or {no}
    a new layer's grid keeps the field of the old one ({yes}) or starts at T0 ({no})
  {init} value = {d6} or {grid} file
    the run's first grid takes each site's temperature from {d6}, or every cell's from a "dump conduction"_dump.html file, instead of T0
  {far} value = R
    passes farther than R from the lattice box ride RKL2 super-steps, and the run ends once the box is done (m, 0 = off)
  {ded} values = zero or more sub-keyword/value pairs
    directed energy deposition: no powder bed, laser-deposited material
    {radius} value = r = birth radius around the laser axis (m)
    {T_birth} value = T = temperature of newly deposited material (K)
    {depth} value = d = births reach d below the laser plane (m) :pre
:ule

[Description:]

The {conduction} temperature source solves nonlinear transient heat
conduction for "app_style additive/texture/kk"_app_additive_texture.html.
It is a finite-volume solver in enthalpy form on the GPU (or whatever
Kokkos backend the build uses).  Unlike the analytic
"rosenthal"_temperature_source_rosenthal.html and
"moser"_temperature_source_moser.html sources, it handles
temperature-dependent conductivity and specific heat, latent heat,
powder, convective and radiative surface losses, and a thermal domain
larger than the lattice box.

The nine positional values have the same meaning as Moser's standard
form.  The heat source is a Gaussian exp(-x^2/sx^2 - y^2/sy^2 -
z^2/sz^2) carrying the absorbed power lambda*Q into the half space below
the laser plane.  sx is therefore the 1/e radius, which is the 1/e^2
radius divided by sqrt(2).  The laser moves along the
"laser_path"_laser_path.html, including {hatch}, {serpentine}, {pause},
{pause_below}, {reset_temperature} and the {laser_path file} form.
{reset_temperature} resets the whole thermal field to that
temperature.

[Grid.]  Inside the lattice box each lattice site is one cell.  Outside
it, cells grow by the factor {stretch} per cell out to {margin} and
{plate}, so a large surrounding domain costs few cells.  The top face of
the grid is the laser plane, put on the top face of the highest site
layer below it.  Sites above the grid read T0.

[Phases.]  Each cell is gas, powder or dense.  Inside the box the phase
is read once from {i2}: 0 or 1 is powder, 2 or 3 is dense, 5 is gas.  A
substrate must therefore be set to {i2} = 3, and powder loaded from a
stitch file is kept.  Outside the box the cell is dense below
{plate_top}; powder within {layer_thickness} of the laser plane; else
dense inside the {part} region (the whole domain if {part} is not
given); else powder.  Powder becomes dense the first time it reaches the
liquidus.  The solver tracks the phase itself and never writes {i2}.

[Baseplate.]  {plate_material} gives the plate a second material: its
density, conductivity, specific heat, latent heat, solidus and liquidus
come from that card (emissivity and convection stay the part's).
Plate cells are the sites with {i2} = 6 and, outside the box, the cells
below {plate_top}, which must be given and should be the plate
surface.  {i2} = 6 is allowed only below {plate_top} + {plate_growth}.
In the microstructure model a plate site is solid like {i2} = 3 and is
a growth parent.  Below {plate_top} + {plate_growth} sites melt and
freeze at the plate's liquidus and solidify back to {i2} = 6; above it
they solidify to {i2} = 3.  Both use the same solid_front_vel law.
Fast-forward and the end of a layer wait for the lower of the two
liquidus and solidus temperatures.  A
cell's material is fixed when the grid is built (once per layer).

[Composition.]  {composition} makes the part's material a function of
each site's composition x, the per-site value d11 (for a graded build,
the mass fraction of the second powder).  The density, conductivity,
specific heat, latent heat, solidus and liquidus come from the cards
at the nodes x1 ... xn: b bins evenly spaced over x1..xn are each
interpolated linearly between the two cards around them (tables on the
union of both cards' temperatures), and a site takes the nearest bin.
x outside x1..xn takes the end bin.  The positional k, alpha and cp
then only set the source (and the default {k_powder}); emissivity,
convection and {k_powder} stay one value for every x.  A lattice cell
takes its site's x; a part cell outside the box takes x1.  In the
microstructure model a site melts at its own bin's liquidus
(additive/texture/kk); fast-forward and the end of a layer wait for the
lowest liquidus and solidus of all bins.  x starts from d11 (set it
per layer or region with "set"); with {mix pool} every liquid site takes
the mean x of all liquid sites at each step, so the pool is well mixed
and a layer is diluted by what it remelts (each site counts equally;
all liquid in the domain is one pool).  With {mix none} x does not
change.  The solid_front_vel law and the
nucleation values are the same for every x.  Example:
examples/am/surge/conduction/in.thin_wall.ded.graded.

[Flow.]  {flow lbm} adds the flow of the melt pool: a D3Q19 lattice
Boltzmann solver on the cells of the lattice box (they are the sites,
cubes of the lattice spacing), run only over the liquid.  A dense cell
above its material's solidus is fluid; solid and powder cells are
no-slip walls; gas (and, with {ded}, unborn) cells above the liquid are
a flat free surface.  The surface does not move: no bead shape, keyhole
or recoil pressure.  The flow is driven by the thermal Marangoni stress
dsigma/dT grad(T) on the surface cells and by buoyancy, and damped in
the mushy zone by a Carman-Kozeny drag C (1-fl)^2/(fl^3+0.001), fl the
liquid fraction between solidus and liquidus.  The defaults are
Ti-6Al-4V-like; give the alloy's own.  The viscosity of liquid metals
is so low that the solver adds a Smagorinsky eddy viscosity for
stability; it is a stabiliser, not a validated turbulence model.

Before each thermal step the flow advances by the same time, in an even
number of flow steps chosen so that the fastest cell moves about a
tenth of a cell per step (the step shortens by itself when the flow is
faster than {u_ref}; the run stops with an error if it runs away), and
the enthalpy is carried with the flow's own mass fluxes by a
flux-limited upwind scheme.  With {composition ... mix flow} the
composition d11 is carried the same way, so mixing in the pool is
whatever the flow does instead of the instant mixing of {mix pool}.  A
uniform composition stays exactly uniform, and the total of d11 is
conserved to about 0.01 percent (0.004 percent over a 4-layer graded
wall; exactly per unit mass, and the lattice Boltzmann liquid is very
slightly compressible).

Liquid properties by composition: {properties cards} (needs
{composition ... mix flow}) takes the liquid's surface tension, density
and viscosity from the \[flow\] sections of the composition's
"material cards"_material.html instead of {dsigma_dT}, {beta} and
{viscosity}, for every cell from its own composition and temperature.
The Marangoni stress is then the surface gradient of the surface
tension itself, so it has a solutal part, dsigma/dx grad(x), beside the
thermal one, and each composition has its own dsigma/dT; where two
liquids of different composition meet at the surface, the flow runs
toward the one of higher surface tension.  Buoyancy comes from the
density, so a denser composition sinks and each composition has its own
thermal expansion.  Between two cards the surface tension and the
dynamic viscosity are mixed linearly in the mass fraction (the surface
tension is each card's value and slope at its own temperature; the
viscosity is each card's value at its liquidus), and the density by
adding volumes.  A linear mix of surface tensions ignores that the
component of lower surface tension gathers at the surface:
{sigma_table file} reads the surface tension from a table of
tools/surface_tension.py instead (rows T x sigma, T outer and x inner,
both uniform; x is d11; linear beyond the table's T range, held beyond
its x range).  The liquid's inertia stays that of one density (a
Boussinesq model): with a large density difference between the end
members the speeds are approximate.  The gradient of the surface
tension is taken between liquid cells only.

New material: under {ded} each layer's sites carry the composition fed
for that layer (d11, set before the run).  With {feed slab} a new cell
simply melts with that composition, as a layer already in place.  With
{feed surface} (needs {mix flow} and {ded}) it enters the way blown
powder does, from above into the pool: a new cell takes the pool's
mean composition when it first melts, and the composition it would
have brought is added to the liquid of the new layer (down to one
layer thickness below the laser plane) under the laser's footprint
exp(-r^2/R^2), R the {ded} birth radius, no cell going past the fed
composition.  Any amount that has found no liquid yet is carried over
and reported when the next layer starts.  The surface itself stays
flat and fixed in both.  While any cell is liquid the laser-off super-steps
({sts}) are replaced by plain steps.  "dump conduction"_dump.html also
writes the velocity (ux, uy, uz, m/s).  On several processes each one
steps the flow in its own cells and exchanges two layers of cells with
its neighbours in x and y (every process needs 2 or more sites along a
split axis); without {feed surface} the result is the same, bit for bit
in double precision, as on one process.  The flow solver and the carrying
scheme are checked against analytical solutions by
tools/melt_flow_check.cpp (build target melt_flow_check).  The flow's
memory follows the pool: about 230 bytes per cell (single precision
kernels) of a block around the liquid, not of the whole box.  Costs
from half again to nearly three times the run time of a {mix pool} run
(the larger on a 20-layer wall whose pool stays liquid for long).  Examples:
examples/am/surge/conduction/in.thin_wall.ded.graded.flow.

[Density.]  One density, rho = k/(alpha*cp), is used for every phase.
Give the dense value and make the model layer the consolidated layer
thickness (the path z step), so that melting a model layer takes the
same energy as melting the real, thicker powder layer.  {packing} f
instead gives powder cells f*rho, kept after they melt.  The microstructure
model does not shrink melted powder, so {packing} below 1 is for
single-layer tests only.

[Evaporation.]  Without it nothing limits the temperature under the
beam, and a concentrated laser drives the surface far past the boiling
point.  {evaporation} adds, on every face where convection and
radiation act, the loss

q = c f sum_i X_i Lv_i p_i(T) sqrt(M_i / (2 pi R T)),  p_i = 1 atm exp(Lv_i M_i / R (1/Tb_i - 1/T)) :pre

the Hertz-Knudsen flux of each species at its Clausius-Clapeyron vapour
pressure, weighted by mole fraction X_i (Raoult's law).  c is
{evaporation_coef}: 0.82 is the fraction that does not recondense when
the vapour expands into vacuum.  f accounts for the gas above the
surface at pressure pa = {evaporation_ambient}: with p = sum_i X_i p_i
the liquid's vapour pressure, f = 0 while p <= pa (the surface is below
its boiling point; the slow diffusion of vapour through the gas is
neglected) and f = 1 - (pa / p)^2.3 above, a fit to Knight's
Knudsen-layer jump conditions.  pa = 0 gives f = 1.  The surface then
settles a little above the local boiling point.  With one species every
metal cell evaporates alike.  With two (needs {composition}) they are
the materials at the two ends of the composition range, and a cell's
mole fractions follow from its composition bin, so the cap rises as the
less volatile species takes over.  Example, Ti (standing in for
Ti-6Al-4V) and Nb: {evaporation 2 3560 8.88e6 0.047867 5017 7.43e6
0.092906}.  Limits: an alloy is one species here (Ti-6Al-4V loses Al
first and boils some 100-300 K below Ti); no mass leaves, only heat; no
recoil pressure.  The loss is steep in T, so the explicit step limit
includes its slope 300 K above the lowest boiling point.

[Directed energy deposition.]  With {ded} there is no powder bed.
Outside the box, cells that powder would fill are gas instead.  Inside
it, sites with {i2} = 0 or 1 are unborn: they are gas, take no laser
energy and are not updated, and the faces next to them lose heat like
faces next to gas.  An unborn cell is born, as powder at {T_birth}, when
the laser is on, its axis passes within {radius} of the cell centre, and
the centre lies less than {depth} below the laser plane.  From then on it
is powder that melts to dense at the liquidus, so the pool pays to heat
and melt the added material; it conducts as the dense material, not at
{k_powder}, because blown powder is no insulating bed (at {k_powder} a
single unmelted row under the pool can keep it from the substrate).  Lay out the bead as
{i2} = 0 in a box that is otherwise {i2} = 5 above the substrate.  Laser
energy that falls on unborn or gas cells is lost, so {radius} should
cover the beam.  At the next layer the phases are re-read from {i2}, so
born material that never melted is unborn again; {depth} keeps it from
being born a second time.  Born cells are born along the path, not a
layer at a time.

[Losses.]  Faces next to gas, and the top face, lose heat by convection
and radiation to T_inf.  The outer faces of the thermal domain are held
at T0 or insulated ({far_bc}).

[Time stepping.]  The solver takes explicit sub-steps at 0.9 times the
stable step, the minimum over cells of each cell's own material limit.
With {plate_material} the more conductive material usually sets it.  Intervals with the laser off are advanced with RKL2
super-time-stepping of up to {sts} stages.  Once the field is below the
liquidus with no pass active, the app fast-forwards to the next pass,
and the skipped interval is still integrated.

[Stitched boxes.]  A run's field starts at T0, so in a chain of
boxes run one after another (a stitched build) a box that starts while
the previous one is still hot would begin cold, and a melt pool carried
across the cut would freeze.  With {init d6} the run's first grid takes
each site's temperature from its {d6} value, as set by the deck before
the run (e.g. "set d6 stitch"_set.html from the previous box's dump),
with the enthalpy of the cell's material; sites with {d6} <= 0 and the
cells outside the lattice box start at T0.  The heat that was in the
previous box's margin cells is lost.  Later grids (a new layer) start
at T0 as before.

With {init grid} file every cell of the first grid, margins included,
takes the temperature of a "dump conduction"_dump.html file (written
by the previous box, e.g. with "dump_modify last yes"_dump_modify.html),
interpolated trilinearly between the file's cell centres at the cell's
centre, with the enthalpy of the cell's material.  Where both boxes'
cells are lattice cells they coincide, so the copy is exact; past the
lattice box the values are sampled, not volume averaged.  Cells centred
outside the file's grid start at T0.  A powder cell outside the lattice
box whose nearest file cell is dense becomes dense (powder the previous
box melted); lattice cells keep the phase their {i2} gives.  The field
is taken as it is at the file's time, which is printed: a gap until the
run's start is not integrated.  A warning is printed when the gap, either
way, is longer than the time heat takes to diffuse one cell (dx^2 /
alpha); set the run's start to the file's time with
"reset_time"_reset_time.html.  {init grid} and {init d6} may both be
given; the grid is read first, then {d6} sets the sites.

[Far passes.]  With {far} R, the laser is far while it is more than R
from the lattice box in x or y.  An interval in which it stays far is
advanced with RKL2 super-steps, like a laser-off interval, with the
laser's path over each super-step deposited as one source: samples at
most sx/2 apart along the path, each the cell-integrated Gaussian.  When
no site is at or above the solidus and none is liquid, the app skips its
steps until the laser next comes within R (fast-forward), and the solver
integrates the skipped interval the same way.  In the last layer, once
no later pass comes within R, the box is done: the field is frozen at
that moment and the run ends ("Box done" in the log), so {run} can be
given the end of the layer instead of a hand-picked stop time.  The
final {d6} is then the field when the box went cold, not at the stop
time.  R must be large enough that a pass beyond it cannot melt the
box: at least the pool half-width plus a margin, e.g. 0.5 mm.  Inside R
the solver is unchanged.  {far} needs {sts} >= 2 and is not allowed with
{ded}.

[Layers.]  A layer is finished when its last pass has emitted, the
maximum temperature is below the solidus, and no site is liquid.  With
{laser_path file} the next layer then starts after the path's recoat
time.  Otherwise the field is reset to T0, the rest of the run is
skipped, and the next {laser_path} and "run"_run.html is the next layer.
A new layer's laser plane rebuilds the grid up to it.  By default the
rebuilt field starts at T0; with {carry yes} every cell the new grid
shares with the old one (all but the new top cells) keeps its
temperature, so heat builds up from layer to layer as in a real build
(e.g. a DED pillar, examples/am/surge/conduction/in.rectangle.ded).
{carry} acts only on the rebuilds within a run (a {laser_path file}
with several layers): a new {laser_path} command still resets the
field to T0.

Solver details, validation against Moser, and the material discussion
are in docs/CONDUCTION_SOURCE.md in the source tree.

[Restrictions:]

Only "app_style additive/texture/kk"_app_additive_texture.html can use
this source; the CPU app stops with an error at its first temperature
query.  It does not support the {keyhole} mode,
"laser_fluctuations"_laser_fluctuations.html, {temperature_smooth},
periodic boundaries, or a "processors"_processors.html grid that splits
z (use processors * * 1).

A word that is not a conduction keyword is an error, as is a number of
positional (Moser) values other than nine.  With {ded}, {layer_thickness}
must be 0 and {packing} 1; the {card} form leaves out the process set's
layer thickness when {ded} is given.

[Default:]

k_table = constant k, cp_table = constant cp, latent = 0, k_powder =
k/100, convection h = 0 (T_inf = 300), emissivity = 0, no evaporation, margin = 0, plate
= 0, stretch = 1.25, max_cell = none, part = whole domain dense,
layer_thickness = 0, packing = 1, plate_top = box bottom, plate_material
= none, plate_growth = 0, composition = none (mix pool when given), beam = gaussian, far_bc = fixed, sts = 32, carry = no, flow off, init T0, far = 0 (off), ded off (when on: radius = 2 sx, T_birth
= T0, depth = the rise of the laser plane since the previous layer,
unlimited for the first).  With a material card loaded, none of these material
defaults (latent, k_powder, convection, emissivity, layer_thickness) is
used: each must come from the card or the command.
