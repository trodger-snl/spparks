temperature_source hdf5_unstructured / hdf5_csr

Syntax: 

setup_temperature_source hdf5_unstructured filename dx threshold_temp default_temp [unused] [grid_cell_mult]
setup_temperature_source hdf5_csr          filename dx threshold_temp default_temp [unused] [grid_cell_mult]
  • filename = path to the HDF5 file holding the FE temperature history
  • dx = lattice spacing in meters (the app's dx); converts site coordinates to meters
  • threshold_temp = temperature (K) above which a site counts as "active"; the fast-forward predictor skips periods with no active site
  • default_temp = temperature (K) of sites not covered by the mesh of the current layer
  • unused = optional placeholder (formerly bounds_check_mode); read and ignored, kept so decks that give grid_cell_mult in this position still work
  • grid_cell_mult = optional positive number, in units of dx (default 100.0): the padding around each rank's subdomain when loading mesh chunks. (It no longer sets the element-search grid, which now covers only this rank's sites and sizes itself.)

Examples: 

setup_temperature_source hdf5_csr "stale_layer_test.hdf5" 5e-06 250.0 300.0
setup_temperature_source hdf5_unstructured thermal_trace.h5 5e-6 1500.0 300.0 0 50.0

See examples/hdf5/stale_layer/in.stale_layer.

Description:

Reads a time-resolved temperature history on an unstructured tetrahedral finite-element mesh from an HDF5 file written by an external thermal solver, and interpolates it onto the lattice sites each step. Selected via setup_temperature_source with type hdf5_unstructured or hdf5_csr.

The file holds a root dataset layerTimes (non-negative, strictly increasing start times in seconds; trailing zeros are trimmed) and one group per layer, named "0", "1", ... Layer i is active from layerTimes[i] until the next layer starts. Each group holds the chunk bounding boxes and pointers (boundingBoxes, elemPtrs, nodePtrs), the mesh (nodeCoords, elementToNode) and the per-node time series (dataCounts, times, temperatures).

When a layer becomes active, each rank loads only the mesh chunks that overlap its subdomain padded by grid_cell_mult * dx, finds the tetrahedron containing each of its sites (owned and ghost), and caches the element and its barycentric weights. Each step the node temperatures are interpolated in time and the site temperature is the barycentric blend of its element's nodes. Sites outside the loaded mesh get default_temp. The per-site temperature intervals above threshold_temp are precomputed per layer and drive the fast-forward predictor, which skips to the next interval when no site is active.

The two variants differ only in how the per-node time series are stored:

  • hdf5_unstructured : times and temperatures are rectangular (nodes, max samples) arrays, padded to the longest series.
  • hdf5_csr : times and temperatures are flat arrays indexed by a nodeOffsets dataset (compressed sparse row), so ragged series need no padding. Use it for large files, where the padded arrays exhaust memory.

With a parallel HDF5 build, the file is opened with MPI-IO and each rank reads only its own chunks. Collective metadata is deliberately not used, because a rank with no overlapping chunk skips reads that other ranks make.

The optional nodal_smooth command (see app_style additive/texture) smooths the node temperatures over the mesh before interpolation; it applies only to the HDF5 sources.

GPU support:

Both variants run in additive/texture and additive/texture/kk. In the Kokkos app the host still reads the file, loads layers and builds the per-site element cache; the device does the per-node time interpolation (or, with nodal_smooth, receives the host's smoothed node values) and the per-site barycentric blend for owned and ghost sites, so no ghost temperature communication is needed. With temperature_smooth enabled the Kokkos app uses the host path.

Restrictions:

The HDF5 sources need a build with HDF5 and HighFive (-DSPPARKS_ENABLE_HIGHFIVE=ON); without it, both stop with an error at setup.

The simulation time must stay within [layerTimes first, last]; a time outside that range is an error.

The laser path is implicit in the temperature history: laser_path in its line form has no effect, its file form is an error, and laser_fluctuations is an error.

Related commands:

setup_temperature_source, temperature_source_rosenthal, temperature_source_moser, app_style additive/texture

Default:

grid_cell_mult = 100.0
