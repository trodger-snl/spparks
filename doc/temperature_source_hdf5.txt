:line

temperature_source hdf5_unstructured / hdf5_csr :h3

[Syntax:]

setup_temperature_source hdf5_unstructured filename dx threshold_temp default_temp [bounds_check_mode] [grid_cell_mult]
setup_temperature_source hdf5_csr          filename dx threshold_temp default_temp [bounds_check_mode] [grid_cell_mult] :pre

filename = path to an HDF5 file containing the unstructured FE thermal trace :ulb,l
dx = SPPARKS lattice spacing in meters (must match {app_style} dx) :l
threshold_temp = temperature (K) above which a site is considered "active";
                 used by the fast-forward predictor to skip cool periods :l
default_temp = ambient / fall-back temperature (K) returned at sites
               outside the FE mesh and at nodes whose recorded time
               trace does not cover the current time :l
bounds_check_mode = optional integer; parsed but currently unused.
                    Default 0. :l
grid_cell_mult = optional positive double, in units of dx: the
                 spatial-grid bin size used for fast point-in-element
                 lookup, and also the padding added to each rank's
                 subdomain when selecting FE chunks to load.
                 Default 100.0. :l,ule

[Examples:]

setup_temperature_source hdf5_unstructured thermal_trace.h5 5e-6 1500.0 300.0
setup_temperature_source hdf5_csr           thermal_trace_csr.h5 5e-6 1500.0 300.0 1 50.0 :pre

[Description:]

Loads a time-resolved unstructured finite-element temperature trace
from an HDF5 file written by an external thermal solver (e.g. Sierra
Aria, Diablo, Albany), and interpolates it onto SPPARKS lattice sites
each timestep.  Selected via
"setup_temperature_source"_setup_temperature_source.html with type
{hdf5_unstructured} or {hdf5_csr}.

The HDF5 file is organized as a sequence of {layers} (one HDF5 group
per pass / scan-line / pause) containing:

{layerTimes} : monotonically-increasing array of layer activation
times (seconds). :ulb,l
per-layer datasets: nodal coordinates, element connectivity, and the
nodal time-temperature traces for the nodes touched in that layer. :l,ule

For each lattice site the source caches the FE element it falls inside
(or "outside mesh" if it falls outside any element in the active
layers) and interpolates the four tetrahedral node temperatures with
barycentric (linear tet) weights; each node's trace is interpolated
linearly in time.  A simulation time before the first or after the
last {layerTimes} entry is an error.  A fast-forward predictor
{get_next_time_with_temperature(current_time, threshold)} walks the
layer table forward to find the earliest time at which any node's
temperature exceeds {threshold_temp}, so the simulation can skip
periods when the laser is off the local subdomain.

The two variants share identical setup, lookup, and interpolation
logic, and differ only in HDF5 storage format:

{hdf5_unstructured} : node temperatures are stored per layer as a
rectangular {(nodes, times)} array.  Simpler format; pads to the
longest per-node trace and is read one chunk at a time, stripping the
padding as it goes. :l,ulb

{hdf5_csr} : node temperatures are stored in compressed sparse-row
form ({nodeOffsets} + flat {times} + flat {temperatures}) so that
ragged per-node traces incur no padding.  Reads merged hyperslabs to
amortize HDF5 metadata cost.  Recommended for sparse / highly-ragged
thermal traces. :l,ule

When SPPARKS is built against parallel HDF5 ({HighFive} +
{H5_HAVE_PARALLEL}), the source uses MPI-IO so each rank reads only
the slabs of nodes that intersect its local subdomain.  Per-rank chunk
filtering is the dominant I/O optimization for large simulations;
collective metadata is intentionally disabled because some ranks may
load zero chunks for a given layer and would deadlock under collective
metadata access.

:line

[Optimizations:]

The HDF5 sources expose three independent performance toggles via the
"app_style additive/texture"_app_additive_texture.html
{temperature_optimization} command:

{spatial_grid} : bin elements into a uniform grid for O(1) point-in-element
queries instead of brute-force O(N_elem). Default on. :ulb,l
{element_cache} : cache the containing element ID per site between
timesteps.  Most sites stay in the same element across consecutive
queries.  Default on. :l
{nodal_precompute} : precompute the per-node temperature at the
current simulation time once per step, then interpolate sites against
those precomputed values.  Requires {element_cache}.  Default on. :l,ule

The {grid_cell_mult} setup-time argument tunes the spatial-grid bin
size; smaller values create more, smaller bins and trade memory for
faster lookup.  It also sets the chunk-load padding, so smaller values
load fewer elements beyond each rank's subdomain.

:line

[Restrictions:]

The HDF5 sources require SPPARKS to be built with HDF5 and HighFive
support; see "Section_start"_Section_start.html for build options.
Without HighFive (and MPI) neither variant is available: the
additive/texture app and all of its temperature sources are left out
of the build.

The HDF5 sources are not path-aware in the SPPARKS sense
({laser_path} has no effect, and {laser_fluctuations} is rejected with
an error): the laser trajectory is implicitly encoded in the FE
temperature trace.
