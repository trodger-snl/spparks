temperature_source rosenthal :h3

[Syntax:]

setup_temperature_source rosenthal standard Q lambda k alpha T0
setup_temperature_source rosenthal aniso    Q lambda k alpha T0 eta_y eta_z
setup_temperature_source rosenthal keyhole  Q lambda_p lambda_l k alpha T0 d \[n_quad\]
setup_temperature_source rosenthal card \[Q v\] \[lambda v\] \[T0 v\] :pre

mode = {standard}, {aniso} (or {anisotropic}), or {keyhole} :ulb,l
Q = total laser power (W) :l
lambda = absorption efficiency (-); absorbed power = lambda * Q :l
lambda_p = absorption efficiency for the surface point source (keyhole only) :l
lambda_l = absorption efficiency for the depth line source (keyhole only) :l
k = thermal conductivity (W/(m K)) :l
alpha = thermal diffusivity (m^2/s) :l
T0 = ambient / preheat temperature (K) :l
eta_y, eta_z = anisotropic stretching factors in y and z (aniso only); both > 0 :l
d = half-depth of the line source over \[-d, d\] (m), keyhole only :l
n_quad = optional Gauss-Legendre order in \[2,64\] for the line-source quadrature (default 8) :l
card = take the {standard} arguments from the loaded "material"_material.html
       card; see "setup_temperature_source"_setup_temperature_source.html :l,ule

[Examples:]

setup_temperature_source rosenthal standard 285.0 0.0775 11.2 2.0959e-6 573.0
setup_temperature_source rosenthal aniso    340.0 0.155 11.2 2.0959e-6 573.0 1.5 0.7
setup_temperature_source rosenthal keyhole  340.0 0.155 0.155 11.2 2.0959e-6 573.0 100e-6 8 :pre

[Description:]

Implements the steady-state moving-frame Rosenthal solution for the
temperature around a point or line heat source moving uniformly over
the free surface of a half-space.  Selected via
"setup_temperature_source"_setup_temperature_source.html with type
{rosenthal}.  All quantities are SI.  Three modes are available.

Rosenthal is the steady-state limit of the unsteady Green's-function
source "temperature_source moser"_temperature_source_moser.html:
Rosenthal assumes the moving frame has reached steady state, while
{moser} integrates an ellipsoidal Gaussian Green's function over the
time history of the laser path.  Choose {rosenthal} when the laser
parameters are constant and a cheap field is enough; choose {moser}
when start-up and end-of-track transients, inter-pass cooling, a
finite spot size, or fluctuations matter.

{standard} : point source on the free surface.  For a site below the
laser plane,

T(R,xi) = T0 + (lambda Q) / (pi k R) * exp(-V (xi + R) / (2 alpha)) :pre

i.e. twice the infinite-medium kernel lambda Q / (2 pi k R) (the
factor 2 is the image source for the insulated surface).  R is the
distance from the source, xi the signed distance along the scan
direction (positive ahead of the source, so the hot tail is at
xi < 0), and V the laser speed set by "laser_path"_laser_path.html.
R is floored at {r_min} (see below).  Sites above the laser plane are
vacuum and get T0.

{aniso} : identical to {standard} except the transverse and depth
coordinates are scaled by {eta_y} and {eta_z} before R is formed,
which fits elongated or bowl-shaped pools without leaving the
analytical framework.  {eta_y} = {eta_z} = 1 reproduces {standard}.

{keyhole} : superposition of two sources sharing the laser path: a
surface point source with absorption {lambda_p} (the conduction lobe)
and a line source with absorption {lambda_l} (the keyhole channel),
integrated along z over \[-d, d\] with {n_quad}-point Gauss-Legendre
quadrature (nodes and weights built once at setup).  Both terms carry
the image factor 2 and share {k}, {alpha} and {V}.  This is the
analytical counterpart of the "moser keyhole"_temperature_source_moser.html
double-ellipsoid model.

:line

[Path and multi-pass behaviour:]

The Rosenthal source needs a "laser_path"_laser_path.html line path
(a run without one stops with an error).  The laser pose is advanced
along the path each step; once the path is exhausted every site gets
T0.  {repeats N} and {hatch S N} passes run back-to-back with no gap.
{laser_path} sets the singularity guard {r_min = 0.5 * dx} (dx = the
app's lattice spacing in meters) so the 1/R prefactor stays finite at
the source.

When no site is above the liquidus, a fast-forward predictor walks a
copy of the path ahead in steps of {fast_forward_search_window} (see
"app_style additive/texture"_app_additive_texture.html) and skips to
the first time a conservative upper bound on the temperature in the
local subdomain reaches the liquidus.

:line

[GPU support:]

All three modes run in both {additive/texture} and
{additive/texture/kk}.  In the Kokkos app the temperature of every
site (owned and ghost) is evaluated on the device, including the
{keyhole} quadrature; the host only advances the laser pose.  With
{temperature_smooth} enabled the Kokkos app uses the host path.

:line

[Restrictions:]

The Rosenthal source is steady state in the moving frame: it assumes
the laser parameters have always had their current values, so it
carries no thermal history.  "laser_fluctuations"_laser_fluctuations.html
is rejected for this source.

Because back-to-back passes are already independent, the {pause} and
{pause_below} keywords of "laser_path"_laser_path.html are rejected
for this source (and therefore {reset_temperature} too).  The
{laser_path file} form is also rejected.  Use the
"moser"_temperature_source_moser.html source for inter-pass cooling
or waypoint paths.

Q, k and alpha must be > 0; lambda (standard, aniso), lambda_p and
lambda_l (keyhole), eta_y and eta_z (aniso), and d (keyhole) must be
> 0, or setup stops with an error.  {n_quad} is clamped silently to
\[2, 64\].  Extra trailing arguments are ignored.

The {card} form supports {standard} mode only.
